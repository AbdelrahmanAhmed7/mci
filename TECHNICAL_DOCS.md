# MediConsult Technical Documentation

## 1. Project Overview

MediConsult is a Flutter application for health insurance member self-service. It uses GoRouter for navigation, BLoC/Cubit for state management, GetIt for dependency injection, Retrofit over Dio for backend API calls, Firebase for messaging/analytics/crash reporting, Easy Localization for Arabic/English language support, and local cache services for offline-friendly repeat access.

## 4. Architecture

### Startup

`main.dart`, `main_dev.dart`, and `main_prod.dart` initialize Flutter bindings, Easy Localization, Firebase, Crashlytics, connectivity, push notifications, dependency injection, login status, onboarding status, saved locale, and then run `MediConsultApp`.

`main_prod.dart` additionally checks for Android in-app updates in non-debug mode. Both default and prod entry points can send a Crashlytics test error outside debug mode.

### Navigation

Routing is centralized in `lib/core/routing/app_router.dart` using GoRouter. The initial route is `/home` when `isLoggedInUser` is true and `/login` otherwise. The route table includes signup, login, password reset, home, approvals, refunds, chronic medicines, profile, personal information, family members, support, e-card, chat, terms/privacy, language, notifications, network, and policy.

### State Management and Dependency Injection

Feature screens use BLoC/Cubit classes registered through `lib/core/di/service_locator.dart`. GetIt registers Dio clients, Retrofit API services, repositories, local data sources, and cubit factories.

### Networking and Auth

`lib/core/network/dio_factory.dart` creates Dio clients with timeouts, error mapping, retry handling, and PrettyDioLogger. The main API client reads `SharedPrefKeys.userToken` and sends it as `Authorization: Bearer <token>`. Login uses a separate Dio client without an auth token. Medicard uses another separate Dio client with only `Accept: application/json` because it targets an external API and intentionally does not send the MCI token.

### Caching and Offline Behavior

`lib/core/cache/cache_service.dart` is a facade over feature-specific cache services for home, family, approvals, notifications, network, support, profile, terms/privacy, and refunds. E-card has its own secure local data source and cache owner resolver. `MediConsultApp` displays an `OfflineBanner` over the routed app.

## 5. Key Modules / Features

### Authentication

Lives under `lib/features/auth`. Includes login, signup, account verified, forgot password, OTP password screen, and reset password. Login persists user/session values and updates the main Dio authorization header after successful login.

### Home

Lives under `lib/features/home`. The home screen loads member/home info, shows plan and request widgets, health/medicine sections, promotions, quick access shortcuts, and bottom navigation.

### Approval Requests

Lives under `lib/features/approval_request`. Supports approval creation with member selection, provider selection, notes, and attachments. Also supports approval history, status filtering/search, member-specific lists, and approval PDF retrieval.

### Refunds

Lives under `lib/features/refund`. Supports refund creation with member, refund type, reason, amount, date, provider, notes, and attachments. Also supports refund history, member filtering, statuses, and refund PDF retrieval.

### Provider Network

Lives under `lib/features/network`. Supports provider category loading, provider search, government/city filters, location-based lookup, list and map presentation widgets, and cached network metadata.

### Medicard Network

Lives under `lib/features/medicard_network`. Uses a separate external API host for network categories, providers, governments, and cities. Provider details navigation is marked TODO.

### Policy

Lives under `lib/features/policy`. Loads policy categories from the backend and navigates to policy detail screens by `categoryId`. `policy_mock_data.dart` remains for test/backward-compatible mock data.

### E-Card

Lives under `lib/features/e_card`. Fetches the member e-card, validates meaningful data, stores it in a secure local cache by owner key, and pre-warms photo/logo image cache entries.

### Profile, Family, and Support

Profile lives under `lib/features/profile`; family members live under `lib/features/family_members`; support lives under `lib/features/support`. These cover personal info, family member list, add family member UI, password change, language selection, FAQ, contact information, insurance plan, logout behavior, and terms/privacy access.

### Notifications

Lives under `lib/features/notifications`. Includes Firebase push notification initialization, local notification handling, notification list loading, badge behavior, mark-as-read by ID, and mark-all-as-read.

### Chat

Lives under `lib/features/chat`. The current chat screen maintains local in-memory messages and simulates agent responses. No backend chat service was found.

### Chronic Medicines

Lives under `lib/features/chronic_medicines`. A screen exists with family member selection, medicine selection UI, lab result upload UI, upcoming lab card, tutorial showcase, and save validation. The home shortcut currently opens a coming-soon dialog instead of navigating to this screen.

## 7. Environment Setup

### Requirements

- Flutter SDK compatible with `>=3.24.0`
- Dart SDK compatible with `^3.9.2`
- Android Studio or VS Code
- Firebase project/configuration for Firebase-backed features
- Node.js/npm only if using `sendNotification.js`

### Install and Run

```bash
flutter pub get
flutter packages pub run build_runner build
flutter run
```

Development flavor:

```bash
flutter run --flavor dev --debug -t lib/main_dev.dart
```

Production flavor:

```bash
flutter run --flavor prod --debug -t lib/main_prod.dart
flutter run --flavor prod --release -t lib/main_prod.dart
```

Build examples from the existing README:

```bash
flutter build apk --release
flutter build appbundle --release
flutter build ios --release
```

Run tests:

```bash
flutter test
flutter test --coverage
```

Node notification utility:

```bash
npm install
node sendNotification.js
```

Do not commit or publish local service-account files or hard-coded test device tokens.

## 8. CI/CD

- Android Fastlane is configured in `android/fastlane/Fastfile`.
